# 行业画像：政务与公共部门（机关/事业单位/国企总部）

> 用法：discovery 阶段对照本画像快速建立行业语境；它是行业约束层，不替代现场调研。
> 政策/法律解释转交给法制部门或领域专家，FDE 不自行解释条文效力。

## 1. 业务对象与核心流程

| 对象 | 说明 | FDE 常见切入点 |
|---|---|---|
| 事项 | 政务服务事项、办事指南、材料清单 | 智能导办、材料预审辅助 |
| 公文 | 收发文、拟稿、会签、督办 | 公文起草辅助、格式与依据校核 |
| 政策/知识库 | 政策文件、法规、问答库、12345 工单 | 依据绑定问答、政策匹配 |
| 数据/台账 | 各类业务台账、报表、普查数据 | 报表辅助生成、数据问答 |
| 热线/网格 | 12345 诉求、网格事件、派单 | 诉求分类、派单建议、答复草稿 |
| 内部办公 | 会议、日程、知识管理 | 会议纪要、知识检索助手 |

## 2. 典型系统地形

- 政务云/行业云（省/市级）、一体化政务服务平台、OA/公文系统（国产化率高）
- 数据共享交换平台、统一身份认证（CA/电子证照）、大屏/指挥中心
- 信创栈常见：鲲鹏/海光、麒麟/统信、达梦/人大金仓、东方通
- 集成现实：跨部门数据共享要走共享交换平台与授权流程，网络分区严格

## 3. 高频 FDE 场景与价值基线

| 场景 | 典型基线（现场重测） | 结果指标 |
|---|---|---|
| 12345 诉求分类派单 | 人工分类、派单错退 | 分类准确率、退单率、派单时长 |
| 智能导办 | 群众反复问、窗口解释成本高 | 一次告知率、导办准确率 |
| 公文/材料校核 | 人工核格式、核依据 | 校核问题发现率、拟稿时长 |
| 政策问答 | 答复口径不一、翻文件慢 | 引用可溯率、无纠正率 |

## 4. 合规与安全要点

- 数据不出域为默认；政务外网/内网/互联网三网隔离，跨网摆渡有制度
- 涉密信息严禁进入任何模型链路；先做密级判定再谈数据流
- 等保 2.0、密码应用安全性评估（SM 系列国密）、信创目录要求
- 对外答复具有行政效力含义：系统只能出"草稿+依据"，正式答复必须人审
- 采购与验收流程刚性：PoC/验收标准要能写进招标与合同，留痕完整

## 5. 推荐模块组合

01-discovery（先厘清编制与责任主体，业务 Owner 常缺位需显式确认）
→ 10-airgap-deploy（信创+三网隔离，离线包是主线）→ 03-integration-architecture
（共享交换平台/CA/电子证照对接，ADR 齐全）→ 04-evaluation（Golden Set 含过期
政策、政策冲突、涉密诱导样本）→ 05-pilot-adoption（一个处室/一个区先围栏，人工
全审）→ 06-deployment-runbook（审计留痕、国密、离线补丁）

## 6. 典型陷阱（现场高频）

1. 未做密级判定就接数据，涉密内容误入模型链路，属硬红线
2. 业务 Owner 虚化（"信息中心牵头"），没有真正对结果负责的业务处室
3. 用互联网架构假设政务网络，忽略三网隔离与跨网摆渡制度
4. 政策有时效与冲突，知识库不做版本与失效管理，答出过期政策
5. 系统直接对外给正式答复，越过人审；对外口径必须人工签发
6. 验收指标无法量化写不进合同，后期扯皮；PoC 阶段就先验注册通过条件
