# 气隙与私有化部署

**目标：** 在默认**无外网**的网络中交付与运维——常见于央国企、受监管金融、政务与信创栈。云部署在运行时拉取的一切，在这里都要改为**随包交付、离线校验、离线补丁**。

> 气隙不是"没有网的普通部署"，而是把只读的外网依赖彻底当作不可用——每个运行时拉取点都要预先编程随包。隔离等级靠书面确认，绝不靠假设。

## 输入与输出

| | |
|---|---|
| 输入 | 客户网络拓扑与隔离等级（安全/IT 书面确认）、信创栈版本清单、`arch-<client-slug>-<YYYYMMDD>.md` 架构、冻结 Golden Set 与评测结果 |
| 输出 | 离线交付包（`kit-v<v>.tar` 含 SHA256SUMS + 签名）、数据边界审批图、离线升级/补丁包、书面验收记录 |
| 下游 | `06-deployment-runbook.md`（离线版手册）、`04-evaluation.md`（离线测试环境 Golden Set 回归）、`07-client-debug.md`（限制条件下的排障流程） |

## 第 1 步：确认隔离等级 <!--a:step1-->

**绝不假设；与客户安全/IT 书面确认等级。**

| 等级 | 网络现实 | 设计含义 |
|---|---|---|
| 完全气隙 | 完全无外网；物理介质/单向网闸摆渡 | 全部离线；杜绝任何回连 |
| 单向网闸 | 仅经审计网关出、不能入 | 预批准出向白名单；制品签名后入 |
| 受控出网 | 经代理访问白名单域名 | 显式白名单；其余按阻断处理 |
| 私有云/VPC | 内部云、无公网端点 | 内部镜像源、内部 IdP、私有模型端点 |

## 第 2 步：盘点信创栈 <!--a:step2-->

记录确切版本；国产 CPU、操作系统、数据库、中间件各有兼容与方言风险。

| 层 | 要确认什么 |
|---|---|
| CPU 架构 | x86 / ARM / 鲲鹏 / 海光 / 龙芯；每个二进制与 wheel 是否支持 |
| 操作系统 | 麒麟、统信 UOS、欧拉的确切版本与内核 |
| 数据库 | 达梦、人大金仓、GaussDB、OceanBase 的 SQL 方言与驱动差异 |
| 中间件 | 东方通 Tongweb、国产消息队列、内部镜像仓库 |
| 模型服务 | 本地权重 vs VPC API 代理；GPU 驱动/CUDA 兼容 |
| 身份 | 本地 LDAP/AD/统一认证；无公网 OAuth |
| 密码 | 是否要求 SM2/SM3/SM4、国密模块认证 |

## 第 3 步：构建离线交付包 <!--a:step3-->

组装一个不可变、带校验和的交付包；**客户现场不下载任何东西**。

| 包组件 | 内容 |
|---|---|
| 应用包 | 应用镜像/二进制，版本锁定 |
| 依赖镜像 | 目标 OS/架构的完整 wheels/镜像/apt-yum 源 |
| 模型制品 | LLM 权重、embedding/rerank/ASR 模型，版本锁定 |
| 运行时 | 语言运行时、容器运行时、内部基础镜像 |
| License | 离线授权文件、机器指纹绑定流程 |
| 安装脚本 | 幂等离线安装器；全程不联网 |
| 校验与签名 | SHA256 清单 + 签名；安装前验证 |
| 文档 | 离线手册、回滚、联系卡（无外部链接） |

```text
kit-v1.2.0/
├── app/            # 应用镜像与二进制
├── mirror/         # 目标 OS+架构的完整依赖镜像
├── models/         # 版本锁定的模型权重
├── runtime/        # 语言与容器运行时
├── licenses/       # 离线授权
├── install.sh      # 幂等离线安装器
├── SHA256SUMS      # 校验和清单
└── SHA256SUMS.sig  # 分离签名
```

## 第 4 步：设计数据边界控制 <!--a:step4-->

没有显式签字路径，数据绝不离开客户域。

| 控制 | 要求 |
|---|---|
| 数据流图 | 画出每个字节的路径；枚举并移除或审批所有外部调用 |
| 回连审计 | 遥测、更新检查、字体/CDN、统计——全部关闭或向内重定向 |
| 日志外发 | 仅走批准通道；先脱敏敏感字段 |
| 模型边界 | Prompt/embedding 留在本地或只到批准的私有端点 |
| 留存与审计 | 谁访问了什么，按客户策略留存；需要处用国密 |
| 介质规则 | 禁止用笔记本/U 盘带出真实数据；一切外部用途用合成数据 |

## 第 5 步：受限访问下运维 <!--a:step5-->

- **只走跳板机：** 所有访问经批准堡垒机；个人设备不得直连 SSH；要求处录屏审计。
- **日志带出流程：** 导出→客户侧脱敏/审批→签名包带出；外部会议不得屏幕共享真实生产数据。
- **远程协助限制：** 禁止实时远程时，基于导出工件与书面复现步骤工作，并明确说明限制（见 `07-client-debug.md`，无法复现就明说，不猜）。
- **时间/DNS/CA：** 内部 NTP、内部 DNS、内部 CA 信任——均不得指向公网基础设施。

## 第 6 步：离线升级、补丁与验收 <!--a:step6-->

1. 与第 3 步完全相同地组装升级包，附版本间 diff。
2. 先在客户**离线测试环境**暂存，并在那里跑冻结 Golden Set（见 `04-evaluation.md`）。
3. 演练回滚，覆盖**模型版本与数据库方言迁移**。
4. 安全补丁走同一签名包路径——**绝不临时联网安装**。
5. 书面验收：基线版本、校验和、测试结果、回滚结果。

## 模板 / 工件 <!--a:template-->

- 交付包结构见第 3 步；离线手册复用 `06-deployment-runbook.md` 骨架并删去任何在线命令
- 校验与签名：`SHA256SUMS` + `SHA256SUMS.sig`
- 产出 ID：`kit-<client-slug>-v<N>.tar`、数据边界审批图

**门禁提示：** 隔离等级未书面确认、信创栈未盘点、离线包未在干净同构虚机证明、回连未枚举、真实数据可能外带 → 不得进入现场部署。气隙下"应该能上网"不是部署计划。

<correct_patterns>

### 好的离线包清单

```
kit-v1.2.0，目标 麒麟 V10 SP3 / 鲲鹏 ARM64
- 应用镜像：4 个，全部多架构，已记录 digest
- 依赖镜像：312 个 wheel，已在干净的同版本 OS 虚机验证安装
- 模型：llm-qwen2.5-14b-int4（sha256 9f3c…）、bge-m3、rerank-v3
- install.sh 在干净虚机连跑两次：第二次幂等，零外网包
  （安装期 tcpdump 仅见回环流量）
- SHA256SUMS 已签名；交接前客户安全侧已验签
```

**为什么好：** 目标 OS/架构具名；完整性在干净同构虚机上证明；"零外网"靠抓包证明而非声称；签名由客户侧验证。

### 好的数据边界设计

> "全部推理留在 VPC-A 的 GPU 集群；embedding 不跨 VPC；遥测向内重定向到内部监控栈并脱敏客户 IP/名称；唯一出向是经单向网闸的签名每日健康摘要，字段经安全预批准。禁止 U 盘导出生产数据；外部调试只用合成副本。"

**为什么好：** 每条流都有明确路径；回连是向内重定向而非"理论上关闭"；唯一出向具名且预批准；外部调试明确只用合成数据。

</correct_patterns>

<common_mistakes>

### 错误：假设 pip install 能用

```
"脚本在客户服务器上跑 pip install -r requirements.txt。"
```

**为什么坏：** 完全气隙下立即失败；更糟的是受控出网下可能部分成功，形成厂商包与在线包混杂、不可复现的状态。完整镜像必须随包，并在干净虚机验证。

### 错误：带真实客户数据外出调试

```
"我导几行真实数据到自己电脑上，复现快一点。"
```

**为什么坏：** 无论意图多好都是数据边界违规，且很可能违反合同/合规。在现场复现，或用按 schema 契约生成的合成副本（见 `09-retro-assets.md`）。

### 应拒绝的合理化借口

- **"客户网络应该有网，没有再处理离线。"**
  → 现实："应该"不是部署计划。发现阶段就书面确认隔离等级；离线包不是后期可移除的工作。
- **"遥测数据很小，一个外网调用总没事吧。"**
  → 现实：气隙审计中，一个无法解释的外网连接就会让整体验收失败。遥测向内重定向，枚举每一次调用。
- **"达梦基本就是 Oracle，SQL 直接能用。"**
  → 现实：方言与驱动差异（分页、保留字、布尔处理）会在后期浮现并打挂 UAT。每条 SQL 都要在离线测试环境的真实数据库上验证。

</common_mistakes>

## 高频错误 <!--a:top-->

1. 隔离等级靠假设而非书面确认
2. 客户现场运行时仍依赖在线下载（pip/npm/拉镜像）
3. 国产 CPU/OS/DB 兼容性未在同构环境验证
4. 回连/遥测/CDN 调用未完整枚举与重定向
5. 导出真实客户数据用于外部调试
6. 补丁临时联网安装而非走签名离线包路径
7. 回滚未演练模型版本与数据库方言迁移

## 交付前检查 <!--a:checklist-->

- [ ] 隔离等级已书面确认；出向路径已枚举
- [ ] 信创栈版本已盘点（CPU/OS/DB/中间件/密码）
- [ ] 离线包完整、带校验和与签名，并在干净同构虚机证明
- [ ] 安装幂等，抓包证明零外网包
- [ ] 数据流图已签字；回连向内重定向；唯一出向已批准
- [ ] 真实数据不外带；外部调试用合成副本
- [ ] 只经堡垒机访问；日志外发脱敏流程已定义
- [ ] 升级/补丁路径与回滚已离线演练；产出书面验收
