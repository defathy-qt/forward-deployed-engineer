> 阶段 S3-4 · 模块 03-integration-architecture。**工件 ID：arch-iris-20260807 + ADR-0011**

## 1. 现有系统地形（6 套 + 2 枢纽）

```
            ┌──────── 生产区（金融专区 · 信创栈 · 强堡垒机）────────┐
 总账 GL ──→│  核心对账文件      ┌──────────────┐                  │
 子账 ─────→│  分户账流水        │ 文件交换平台   │──对账批落地─→┐     │
 资金 ─────→│  资金清算文件      │ (exchange)    │            ▼     │
 计提 ─────→│  计提明细          └──────────────┘      ┌──────────┐ │
              ESB（服务总线，点对点/事件）───────────→ │ 分析体     │ │
   (只读镜像, 不写回)                                  │ (只读方格) │ │
                        ↑ 授权门(双签)                 └──────────┘ │
 总账过账 ←── 人工经办录入 ──── 建议草稿（经授权门）◀───────────┘     │
                   审计事件流 → 审计域（不可变追加）                     │
            └───────────────────────────────────────┴──────────┘
```

- **信创**：麒麟 + 达梦；**专区 + 强堡垒机**（人与访问均过堡垒），配套 **10-airgap-deploy** 全程在场。
- **数据边界**：生产库 → 只读镜像（每日快照）；分析体只见**脱敏/分户级**科目+金额，不带户名。

## 2. 业务本体层（对象/关系/动作/规则/权限）

| 层 | Iris 实例 |
|---|---|
| **对象** | 对账批次、对账文件、差异（单）、科目映射（subject_mapping）、建议草稿、授权记录、审计事件 |
| **关系** | 文件按 `(机构, 币种, 科目)` 对齐；差异挂 `(对账批次, 文件批号, 原始凭证号)`；科目映射 `科目→归属系统+生效日期+状态` |
| **动作** | 归因（读）、起草建议（读+草稿）、提交建议（→授权门）、**过账/调账（永远人工）**、改映射（人工授权门） |
| **规则** | 同科目同币种比对；单向差异需有凭证支撑；漂移=快照与当前差异→预警；**借贷方向无法解释 → 转人工（不猜）** |
| **权限** | 系统=只读授信（Subject）、RO=读+接单/拒绝+草稿、科目管理员=映射**写需授权门**、审计=只读审计域 |

## 3. 身份 → 授权 → 人工授权门 → 审计（贯穿主线）

```
身份(IDP接管) → 授权(角色矩阵) → 系统顶动作=「建议草稿」  →  人工授权门
                                    ↑                        （经办拟+授权复核双签，或拒绝）
      写生产(过账/改映射) = 永远走授权门，系统不另设旁路
                                    ↓
        审计事件流(追加式): 操作人 / 依据(映射快照+凭证号) / 决策 / 时间
```

- **无旁路原则**：系统没有"跳过授权门"的隐藏开关；runbook 校验该项。
- **拒绝即留痕**：RO"拒绝并说明"也算审计事件 + golden 回归输入。

## 4. 防腐层（对外不对内）

- 对 **ESB/文件交换**：统一 `文件收口` 适配层——schema 钉在契约，漂移→预警（复用 `connector-sftp-watcher` 语义）。
- 对 **科目映射**：**锁 + 只读授信**，任何变更必须经人工授权门并写审计。
- 对 **RO 界面**：只能消费「归因+草稿+依据」，无生产写权限。
- 对 **监管/报送**：本系统不提供出口，规避合规风险面。

## 5. 资产复用（1→N 演示）

- **AM-connector-sftp-watcher-v1.2.0**（来自物流样例，born in 电商客户 #3）本处**直接采用**承载"文件交换平台 → 分析体落地 + schema-pin + drift 预警"，零改写；其漂移语义从"SFTP 列数漂移"平移为"文件批版本漂移"。
- **学习点**：资产复用的前提是契约化 input/output + `applies_when/does_not_apply` 可判，详见 09-retro-assets 与仓库 assets/。

## 6. 对抗威胁与对策（节选）

| 威胁 | 对策 |
|---|---|
| 越权提取（拖户名/余额批量） | 只读镜像无户名列；**对抗用例**入 golden set（GS-031） |
| 映射被偷偷改 → 归因全错 | 锁 + 授权门 + **漂移检测**（呼应 wms ISS 的教训） |
| 伪依据（引用不存在的凭证） | 依据层评分：凭证号必须解析到当日镜像；伪造=0 容忍 |
| 不可逆误过账 | 顶部动作仅"草稿"；过账入口在总账侧且双签——架构层杜绝 |

## 7. ADR-0011：科目映射表锁定 + 只读授信

```
状态：已采纳（2026-08-07）   影响：03-arch / 04-eval / 05-pilot / 06-runbook
背景：科目管理员仅 1 人，历史 8-08 未通知修改引发单次归因全错（危机仅因值班在场）；
      任何"机器自动改映射"提议均被否决。
决策：app 对 subject_mapping 只读；写=人工授权门；变更前强制 diff 快照 + 告警。
替代方案：A 机器自动同步（否：权威性单一事实源原则）；B 双写双主（否：复杂度）
后果：归因始终锚定"当日有效快照"；映射变更成为有审计事件的动作。
```

## 8. 部署拓扑补充（关联 10-airgap-deploy）

- 专区两网隔离：分析体部署在**离线内网**，更新包走 **U 盘单向摆渡** + 哈希校验（offline-upgrade）。
- 强堡垒机：所有交互会话录屏 + 双人复核；应用侧禁用外联域名。
- 数据不出专区：Golden Set 全部合成，评测在区内执行。
