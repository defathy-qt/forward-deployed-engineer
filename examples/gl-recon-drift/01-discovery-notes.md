# 发现会议室纪要（脱敏）— GL 对账·调账预审 / Iris Bank

> 阶段 S1 · 模块 01-discovery。**工件 ID：DSC-iris-20260804-01**
> 全脱敏：人名=角色、库表=别名、金额=合成。会计准则是公开的，账本是私有的。

## 1. 客户的一句话（原话转述）

> "我们想要一个**对账机器人**，月结的时候自动把差异平掉，年底 jīng 对（监管报送）前账不平很丢人。"

## 2. 需求还原：问题 / 症状 / 假设 三分

| | 听到的（症状） | 在场证据 | 真问题（假设验证后） |
|---|---|---|---|
| 现象 | "月结对账要 3 天，太慢" | 8 月月结工单日志：RO 手工拉 6 张表比对 | **时长**：月结整体 3 天（同行头部 ~1.5 天），其中**差异定位**占 ~1 天 |
| 痛处 | "一台机器帮我们平账最好" | 无任何权限可直接过账；调账需「经办+授权双签」 | **单笔差异人工定位 ≈ 40 分钟**（日志采样 96 笔），一次定位率仅 61% |
| 隐患 | "季末对不平，常被口头发问" | Q2 末账账差异率 **11%**、账实差异率 9% | 差异**归因不清**是核心：不是差异多，是"说不清为什么" |

**结论**：客户的真问题不是"缺机器人"，是 **差异归因慢且说不清 → 月结时长 3 天 + 季末差异率 11%**。机器人自动平账既超权限（不可逆）又答错题。

## 3. 是否该用 AI？路由检查（五问）

1. 任务是否**闭环可判**？→ 差异归因有明确判定（金标准=会计小组复核）✅
2. 是否存在**可留存的判断记录**？→ 历史调账凭证 + 工单 + 业务台账 ✅
3. 错误代价可控/可围栏？→ 系统只出草稿，人工授权门 → 可围栏 ✅
4. 输入可批量化、可版本化？→ 文件交换平台按日/月产对账文件，schema 可钉 ✅
5. 客户有持续改进意愿？→ 会计室主任牵头，8 月月结即验收窗口 ✅

→ **适合用 AI**（围栏形态：归因+草稿+授权门），非"全自动平账"。

## 4. 现状工作流五要素（基线）

- **触发**：每月 1 日 06:00 文件交换平台拉起上月全量对账文件；T+0 由资金部补一次特殊项
- **参与者**：RO（对账岗）×2、科目管理员（科目映射表维护）×1、会计室主任（授权）
- **主链**：拉 6 套系统文件 → RO 手工比对（6 张表交叉）→ 定位差异 → 拟调账意见 → 双签 → 总账过账
- **辅助链**：科目映射表（subject_mapping）每周一由科目管理员刷新；本月 8-08 曾未通知修改一次（见 ISS）
- **依据**：科目映射表快照、当日总账余额表、原始凭证编号

## 6. 关键约束（写进入口判断）

- **不可逆动作**：过账、调账 **绝不放权**——这是监管与内控硬线，也是本样例的立身红线。
- **数据边界**：只读镜像进入分析体；客户户名/余额只在"越权提取"对抗用例中被刻意封堵。
- **环境**：金融专区 + 信创栈（麒麟/达梦）+ 强堡垒机 → **10-airgap-deploy** 从 S3 起作为架构输入。
- **授权链**：调账建议草稿的**采纳=经办录入+授权人复核双签**，任何系统都不替代。
